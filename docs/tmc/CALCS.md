# Формулы `scripts/tmc_calc.py`

Каждая формула скрипта перенесена из вендорских калькуляторов в
`docs/tmc/*.xlsx` (происхождение файлов — `SOURCES.md`) либо из установленного
Klipper. Ниже — карта «лист/ячейка → формула → функция скрипта». Правило
проекта: новая формула попадает в скрипт только после того, как она описана
здесь.

## 1. Тактирование и единицы

| Источник | Формула | Скрипт |
|---|---|---|
| `Chopper Parameters!C9` | `fCLK = 12 МГц` (внутренний генератор, как у Klipper `TMC_FREQUENCY`) | `TMC_FREQUENCY` |
| `Chopper Parameters!C10` | `tCLK = 1 / (10^6 · fCLK[MГц]) = 83.33 нс` | `TCLK` |

Время в формулах — секунды, индуктивность — генри, токи — амперы. В CLI
индуктивность задаётся в мГн (`--l-mh`, `"inductance_mh"`), поэтому скрипт
делит её на 1000 перед подстановкой.

## 2. Ток: регистры CS/IRUN (информационно)

Klipper сам переводит `run_current` в регистры, поэтому скрипт **не печатает**
`driver_CS`/`driver_IRUN`: он только воспроизводит расчёт Klipper для сверки,
чтобы в модуле не появилось противоречие между `run_current` и регистрами.

| Источник | Формула | Скрипт |
|---|---|---|
| `klippy/extras/tmc2130.py` `TMCCurrentHelper._calc_current_bits` | `CS = round(32 · (RS + 0.020) · I_RMS · √2 / VREF) − 1`, `VREF = 0.18` при `VSENSE=1`, `0.32` при `VSENSE=0`, затем ограничение `0..31` | `current_2209` |
| там же `_calc_current_from_bits` | `I_пик = (CS+1) · VREF / (32 · (RS + 0.020))`, `I_RMS = I_пик / √2` | `current_bits_to_peak_2209`, `current_bits_to_rms_2209` |
| `klippy/extras/tmc5160.py` `TMC5160CurrentHelper._calc_globalscaler` | `GLOBALSCALER = round(I_RMS · 256 · √2 · RS / 0.325)`, минимум `32`, `≥256 → 0` | `current_5160` |
| там же `_calc_current_bits` | `IRUN = round(I_RMS · 256 · 32 · √2 · RS / (GSCALER · 0.325) − 1)`, ограничение `0..31` | `current_5160` |
| там же `_calc_current_from_field` | `I_RMS = GSCALER · (IRUN+1) · 0.325 / (256 · 32 · √2 · RS)` | `current_5160` |

Причина: `run_current` в конфиге — единственный источник истины, а `driver_*`
регистры тока в Klipper отсутствуют. Выводятся только комментарии `# сверка: …`.

Лимит IC для проверки входных данных:

| Драйвер | Формула предела | Пример (RS из парка) |
|---|---|---|
| TMC2209 | `VREF_VSENSE0 / ((RS + 0.020) · √2)`, дополнительно ограничен `MAX_CURRENT = 2.0 A` из Klipper | 1.741 A при `RS = 0.110` |
| TMC5160 | `0.325 / (RS · √2)`, дополнительно `MAX_CURRENT = 10 A` | 3.064 A при `RS = 0.075` |

`run_current = min(I_ном · --i-factor, предел IC)`. Если **номинал** мотора
выше предела IC, скрипт отказывает (код 2): такой мотор этим драйвером на
номинале не питается, нужно уменьшать `--rsense` или брать другой драйвер.

## 3. SpreadCycle: blank/slow-decay и гистерезис

### TMC2209 — лист `Chopper Parameters`

| Источник | Формула | Скрипт |
|---|---|---|
| `C13` | `tBLANK = tCLK · (16 + 8·TBL)` (TBL 0..3 → 16/24/32/40 tCLK) | `tblank` |
| `C21` | `tSD = tCLK · (24 + 32·TOFF)` | `slow_decay_time` |
| `C23` | `dI_BBM = VM · 200 нс / L` | `chopper` |
| `C24` | `dI_blank = VM · tBLANK / L` | `chopper` |
| `C25` | `dI_SD = R · I_пик · 2 · tSD / L` | `chopper` |
| `C30` | `HystStart_MIN = MAX(0.5 + (dI_BBM + dI_blank + dI_SD) · 2 · 248 · (CS+1) / I_пик / 32 − 8; −2)` | `chopper` |
| `C33` | `HSTRT_desired = MAX(MIN(HystStart_MIN, 8), 1)` | `chopper` |
| `F33` | `HSTRT = HSTRT_desired − 1` | `chopper` |
| `C34` | `HEND_desired = MIN(HystStart_MIN − HSTRT_desired, 12)` | `chopper` |
| `F34` | `HEND = HEND_desired + 3` | `chopper` |
| `C38` | `fCHOP_предел = 1 / (2·tSD + 2·tBLANK)` | `chopper` |

### TMC5160 — лист `Chopper Parameters`

| Источник | Формула | Скрипт |
|---|---|---|
| `C13` | `tBLANK = tCLK · 16 · 1.5^TBL` (1.333/2/3/4.5 мкс) | `tblank` |
| `C21` | `tSD = tCLK · (12 + 32·TOFF)` | `slow_decay_time` |
| `C23` | `dI_blank = VM · tBLANK / L` | `chopper` |
| `C24` | `dI_SD = R · I_пик · 2 · tSD / L` | `chopper` |
| `C29` | `HystStart_MIN = MAX(0.5 + (dI_blank + dI_SD) · 2 · 248 · (CS+1) / I_пик / 32 − 8; −2)` | `chopper` |
| `C32/F32` | `HSTRT_desired = MAX(MIN(HystStart_MIN, 8), 1)`, `HSTRT = HSTRT_desired − 1` | `chopper` |
| `C33/F33` | `HEND_desired = MIN(HystStart_MIN − HSTRT_desired, 12)`, `HEND = HEND_desired + 3` | `chopper` |
| `C37` | `fCHOP_предел = 1 / (2·tSD + 2·tBLANK)` | `chopper` |

Отличие листов: у TMC2209 в сумму входит падение за время `BBM ≈ 200 нс`, у
TMC5160 оно не учитывается. Это не ошибка переноса — так в источниках.

### Округление и границы регистров

* `HSTRT` — `floor(HSTRT_desired − 1)` с ограничением `0..7`;
* `HEND` — `floor(HEND_desired + 3)` с ограничением `0..15` (поле трактуется
  как знаковое `−3..12`, поэтому «желаемое» значение и сдвиг `+3` — из листа);
* Excel хранит дробные `F32/F33`, регистры целые. Скрипт берёт **нижнюю**
  границу, потому что лист называет результат «minimum value which should be
  considered for HSTRT/HEND». Допуск при сверке — ±1 LSB.

### Подсказки листа, перенесённые в предупреждения

| Ячейка | Условие | Сообщение скрипта |
|---|---|---|
| `C28` (2209) / `C27` (5160) | `CS < 16` | «CS мал, значения выше 16 дают лучшее микрошагание» (примечание) |
| `B36`/`C36` | `HystStart_MIN > 20` | снизить TBL/шунт/VM или ток |
| `C36` | `15 < HystStart_MIN ≤ 20` | держать `CS ≤ 30` |
| `B39`/`C39` | `fCHOP_предел > 50 кГц` | поднять гистерезис, измерить реальную частоту |
| `C39` | `fCHOP_предел < 20 кГц` | увеличить `TOFF` (частота может быть слышна) |

## 4. Окно напряжения питания мотора

| Источник | Формула | Скрипт |
|---|---|---|
| `C41` (2209) / `C40` (5160) | `U_ном = R · I_пик / √2` | `motor_voltage_window` |
| `C43`/`C42` | `VM_max = 20 · U_ном` | `motor_voltage_window` |
| `C44`/`C43` | `VM_min = 2 · U_ном` | `motor_voltage_window` |

Это правило листа («чтобы избежать лишнего нагрева мотора от чоппинга»)
печатается как **примечание**, а не предупреждение: парк осознанно питает
низкоиндуктивные LDO-моторы от 48 В, что выше `20·U_ном`. Жёсткой ошибкой
считается только выход за пределы самого драйвера (`VM_RANGE`: 2209 —
4.75…29 В, 5160 — 8…60 В) и предупреждение выше 28 В / 56 В.

## 5. Подбор шунта (информационно)

| Источник | Формула | Скрипт |
|---|---|---|
| 2209 `C47` | `RS(VSENSE=0) = (CS+1)/32/I_пик · 0.32 − 0.020` | `sense_resistor_for` |
| 2209 `C48` | `RS(VSENSE=1) = (CS+1)/32/I_пик · 0.18 − 0.020` | `sense_resistor_for` |
| 5160 `C46` | `RS = (CS+1)/32/I_пик · 0.32` | `sense_resistor_for` |

Печатается в `--json` (`sense_suggestion`), в конфиг не попадает.

## 6. Что скрипт сознательно НЕ считает

| Тема | Причина |
|---|---|
| `PWM_OFS`/`PWM_GRAD` для StealthChop | Приближённые формулы даташита (`PWM_AMPL`, `PWM_GRAD` через `C_BEMF`) вставлены в PDF картинками, а в сохранённых xlsx их нет. По правилу «формулы только из CALCS.md» числа не синтезируются: модуль оставляет автотюнинг StealthChop2 (`PWM_AUTOSCALE`/`PWM_AUTOGRAD`, значения Klipper по умолчанию) и принимает измеренные значения через `--pwm-ofs/--pwm-grad` |
| `driver_TPFD` для TMC2209 | В установленном Klipper `tpfd` есть только у TMC5160 (`tmc5160.py`, значение по умолчанию 4). `tmc2209.py` такого ключа не читает, Klipper упал бы на неизвестном поле |
| `driver_CHM/VHIGHFS/VHIGHCHM`, `FD3`, `TPFD`, CoolStep-поля | Остаются на значениях Klipper; лист их не рассчитывает. Скрипт их не печатает |
| Порог `stealthchop_threshold` в мм/с | Требует `step_distance` из геометрии профиля: параметр принимается сырым (`--stealthchop-threshold`) |
| `driver_SGT`/`driver_SGTHRS` | Калибруется на живом принтере (`SET_TMC_FIELD`). `--sgt auto` печатает только диапазон и стартовую точку, число печатается лишь при явном `--sgt N` |

## 8. Сверка с боевыми конфигами парка

`run_current` парка консервативнее правила «0.8 × номинал» — это результат
тепловых испытаний, а не расчёта:

| Комбинация | В конфиге | `tmc_calc.py` (factor 0.8) | Комментарий |
|---|---|---|---|
| TMC5160 + LDO-42STH48-2804AC | 1.697 A | 2.24 A | парк использует factor ≈ 0.61 и `TBL=0`, чтобы уложить `HystStart` (L = 0.6 мГн) |
| TMC5160 + 17HM19-1684 | 0.951 A | 1.344 A | factor ≈ 0.57 в парке |
| TMC2209 + 17HM19-1684 | 0.800 A | 1.344 A | factor ≈ 0.48 в парке |
| TMC2209 + 17HS4401S (Z) | 0.600 A | 1.360 A | factor ≈ 0.35 в парке |

Для повторения боевых значений используйте `--i-factor` (например,
`--i-factor 0.61` для LDO на TMC5160). Скрипт даёт стартовую точку и полный
набор chopper-регистров, а не заменяет тепловые испытания.
